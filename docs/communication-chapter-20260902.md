# 通信系统设计

> 说明：本文为比赛提交文档的通信章节草稿。文内以 `<尖括号>` 标注的地址为现场
> 实测/固定值，提交前替换为实际数值即可。

## 1. 概述

本系统的通信设计围绕机载自主探索任务的三个核心需求展开：**远程监控与维护**、
**机载计算单元与控制单元的实时指令传输**、**传感器高速数据采集**。系统采用
"多网段物理隔离、专用链路承载控制、多重安全机制冗余"的设计原则：

- 管理、控制、传感三类数据分网段承载，链路之间相互隔离，避免相互干扰；
- 控制指令采用自研报文协议，具备校验、序号与超时保护机制；
- 任一链路异常时均具备快速切断能力，控制权可随时由飞手接管。

## 2. 通信总体架构

系统由三条相互隔离的通信链路构成：

1. **校内网管理链路**：机载计算单元（Orange Pi 5 Max）以原生网卡接入校内网络，
   并通过内网穿透为研发端提供 SSH 远程维护、镜像仓库访问与可视化平台连接；
2. **USB 热点控制链路**：机载计算单元通过 USB 无线网卡建立独立热点，控制单元
   （Manifold 妙算）作为唯一终端接入并获得固定地址，该链路专用于传输速度控制指令；
3. **LiDAR 有线传感链路**：机载计算单元有线网口与激光雷达（MID-70）独立组网，
   专用于点云数据的高速可靠传输。

| 链路 | 承载数据 | 网段/接口 | 传输方式 |
|---|---|---|---|
| 管理链路 | 远程维护、可视化、镜像传输 | 校内网（DHCP） | 内网穿透隧道 |
| 控制链路 | 速度控制指令 | USB 热点固定网段 | UDP 19090，20 Hz |
| 传感链路 | LiDAR 点云 | `192.168.1.50/24` ↔ `192.168.1.119` | 有线直连 |

三条链路在物理与逻辑上互不交叉：校内网承载管理数据，热点专用于妙算通信，有线
网段承载激光雷达数据，从根源上避免数据面与控制面的相互影响。

## 3. 管理链路：校内网接入与远程访问

机载计算单元以原生网卡接入校内网络，地址由校内 DHCP 分配。研发端与机载计算
单元通常不在同一局域网内，因此通过 **frp 类内网穿透隧道** 实现远程访问，隧道
按固定的服务端地址工作，机载端校内地址的变化不影响链路可用性。

隧道当前承载三类远程服务：

| 服务 | 说明 |
|---|---|
| SSH 远程维护 | 经隧道或校内直连访问机载计算单元 |
| 可视化平台 | Foxglove WebSocket，浏览实时点云、规划轨迹与相机预览 |
| 镜像仓库 | 算法/驱动镜像的远程同步（亦可采用离线方式传输） |

镜像传输提供两种方式备选：经隧道暴露镜像仓库端口后在线拉取，或离线同步镜像
归档文件后在本机加载。两种方式均保持部署内容一致。

## 4. 控制链路：自研报文协议

### 4.1 链路组成

控制链路是系统安全的关键路径，完整链路为：

```text
规划器输出 → 速度适配器 → 自研 UDP 报文（20 Hz）→ 妙算 PSDK 桥接 → DJI 飞控控制接口
```

机载计算单元内的规划器生成运动指令，经自研速度适配器完成坐标系转换与限幅后，
封装为自研报文经热点链路发送至妙算；妙算端的 PSDK 桥接程序负责报文校验，通过
DJI 官方控制接口驱动无人机执行。

### 4.2 报文协议设计（DAIB v1）

控制报文为自研二进制格式，字段设计如下：

| 字段 | 说明 |
|---|---|
| 魔数/版本/类型 | 报文标识与协议版本 |
| 校验码 | CRC32，校验报文完整性 |
| 序号 | 递增序号，用于检测丢包与乱序 |
| 时间戳 | 微秒级，用于链路时延监测 |
| 控制量 | 四元组 {x, y, z, yaw}，即三轴速度与偏航角速度 |

发送周期为 20 Hz；速度与偏航量均经限幅（联调阶段水平 0.1 m/s、垂直 0.05 m/s、
偏航 0°/s；生产默认 0.5 m/s、0.2 m/s、3°/s），偏航由目标航向与机头航向的闭环
计算生成，避免直接转发规划器原始量。

### 4.3 可靠性设计

控制链路的可靠性由四层机制共同保证：

1. **完整性校验**：CRC32 与递增序号双重校验，任一报文异常即丢弃；
2. **超时保护**：接收端超过 200 ms 未收到有效报文，立即输出中性指令（全零），
   防止执行陈旧指令；
3. **权限管理**：PSDK 控制权由状态机统一管理——获取、释放、武装、异常确认均有
   明确流程；飞手可通过遥控器随时夺回控制权，系统检测到权限离开后自动停止输出；
4. **降级路径**：链路异常（丢包、超时、权限丢失）时系统停止指令输出，由飞手
   人工接管；故障排除并重新确认链路状态后，方可恢复自动控制。

## 5. 传感链路：LiDAR 有线隔离网

机载计算单元有线网口与 MID-70 激光雷达独立组网（`192.168.1.50/24` 网段），
专用于点云数据传输：

- **物理隔离**：该网段不设默认网关，与校内网、热点链路互不交叉，保证点云数据
  不受其他通信流量影响；
- **反向路径过滤关闭**：为适配雷达的组播广播接收机制，该网段关闭反向路径过滤，
  确保点云稳定到达；
- **启动自检**：系统启动时强制校验网口地址、直连路由与过滤状态，任一不匹配即
  拒绝启动雷达驱动，杜绝"进程正常但无数据"的隐性故障。

雷达以 10 Hz 频率发布点云数据，由机载计算单元内的激光惯性视觉里程计实时消费，
用于建图与自主探索。

## 6. 图传与数传

**图传（视频回传）**：系统视频回传由可视化平台承载——飞行模式下提供 6 Hz 的
低延迟相机预览流（采用丢帧优先策略，网络拥塞时降低帧率而非累积延迟），观察与
回放模式下提供全量话题流。预览流经管理链路（校内直连或穿透）访问。原始 30 Hz
图像数据量大，默认不直接推送，仅在排查图像质量与同步问题时按需启用。

**数传（遥测传输）**：本系统未使用电台类数传设备；遥控链路与机体自带图传由
飞控厂商（DJI）提供，不在本系统范围内。系统自身的遥测信息（状态、日志、点云）
均经管理链路回传。

## 7. 通信可靠性设计总结

| 机制 | 作用 |
|---|---|
| 多网段物理隔离 | 管理/控制/传感数据互不干扰 |
| CRC32 + 序号校验 | 报文完整性、丢包乱序检测 |
| 200 ms 超时中性化 | 链路中断时立即停止执行陈旧指令 |
| 权限状态机 + 遥控夺权 | 控制权始终可被飞手接管 |
| 观察模式指令隔离 | 未验证前不向飞控发送任何控制指令 |

上述机制共同保证：任一链路异常时，系统均以"停止输出、人工接管"为兜底，不
存在无保护的控制指令执行路径。

## 8. 小结

本系统通信设计以三条物理隔离的链路分别承载管理、控制与传感数据：校内网链路
配合内网穿透满足远程维护需求；USB 热点专用链路配合自研 DAIB v1 控制协议实现
低延迟、强校验的控制指令传输；有线隔离链路保障激光雷达数据稳定采集。控制链路
的四层可靠性机制（校验、超时、权限、降级）确保通信异常时的安全兜底。整体设计
体现了"专用链路承载关键数据、多重机制保障链路安全"的工程思路。
