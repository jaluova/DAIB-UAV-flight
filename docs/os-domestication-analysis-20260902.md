# 操作系统国产化分析

## 1. 评分项与结论

> 评分项：本系统所使用的**操作系统**为国产化技术且自主可控。

**结论先行：本系统业务全链路运行于国产开源操作系统 openEuler 24.03 LTS SP4 的
容器用户态之上，操作系统层判定为国产化技术且自主可控（✅）。**

## 2. openEuler 的国产身份与选型

### 2.1 国产身份

openEuler 是国产开源 Linux 发行版，前身为运行于华为通用服务器上的 EulerOS；
2021 年 11 月，华为携手社区伙伴将 openEuler 正式捐赠给**开放原子开源基金会**，
由开源社区持续治理与演进 [1][2]。

openEuler 已成为国内信创基础设施的主流国产开源操作系统之一，统信软件（DDE
桌面、迁移工具等自研特性）、麒麟等信创生态厂商均在其上开展共建 [3]。

### 2.2 选型理由

1. **ARM64 官方一级支持**：openEuler 官方提供 AArch64 架构的完整安装与运行支持
   [4]，与国产化硬件平台（瑞芯微 RK3588，见《芯片平台选型与国产化分析》）原生匹配；
2. **机器人软件栈实际可用**：openEuler ROS SIG 官方维护 ROS 软件源，持续推进
   ros1-noetic 相关软件包的完善与适配 [5]；本项目基于该生态完成了 ROS Noetic
   的实机构建与部署验证（见 §5）；
3. **信创判定口径一致**：openEuler 与麒麟、统信等同为基于 Linux 内核的发行版，
   国产化认证的判定对象是**发行版与用户态运行环境**，并非内核（内核为各发行版
   统一的开源 Linux 生态，同源共享）——本系统的国产化判定采用同一标准；
4. **生态开放、无供应商锁定**：openEuler 由开放原子基金会治理，源码开放、
   可获取、可修改，符合自主可控的判定要求。

## 3. 容器化承载架构

本系统以**容器化**方式承载业务，部署架构如下：

```text
┌────────────────────────────────────────────────────┐
│  业务层：FAST-LIVO2 / DAIB-Explorer / EGO-Planner   │
│          PSDK 适配器 / Foxglove / ROS Master        │
├────────────────────────────────────────────────────┤
│  openEuler 24.03 LTS SP4 容器用户态（aarch64）       │
│  glibc、系统库、运行时、ROS Noetic 全部来自该发行版   │
├────────────────────────────────────────────────────┤
│  宿主内核（Linux 上游 + Rockchip BSP，仅硬件抽象）    │
│  设备驱动装载、容器运行时                           │
├────────────────────────────────────────────────────┤
│  RK3588 国产 SoC 硬件平台（Orange Pi 5 Max）        │
└────────────────────────────────────────────────────┘
```

- **业务 100% 运行于 openEuler 用户态**：ROS 通信、SLAM、探索、规划、控制指令
  生成的全部进程均在 openEuler 容器内运行，所有运行库依赖均来自 openEuler 发行版；
- **容器化的架构价值**：内核与设备驱动由宿主统一提供（驱动随 Rockchip 内核 BSP
  发布），业务层与宿主用户态零耦合——业务既不依赖宿主发行版组件，也不感知宿主
  版本，为操作系统层面的平滑迁移（§4）提供了结构保证；
- **镜像化交付**：算法与驱动以 openEuler ARM64 基础镜像构建，部署可复现、前后
  环境一致。

## 4. 与宿主系统的关系（如实披露与架构论证）

**如实披露**：本系统板卡宿主安装为 Ubuntu 22.04 LTS（通用国际发行版），该宿主
在系统中的角色**仅限**：提供 Linux 内核与设备驱动装载、运行容器运行时。

**架构论证**：

1. **业务零宿主依赖**：全部业务进程运行于 openEuler 容器用户态，不依赖宿主的
   任何用户态组件；宿主对业务而言仅是"内核 + 容器运行时"两个可替换部件；
2. **判定口径统一**：信创 OS（openEuler、麒麟、统信）本身即 Linux 内核发行版，
   国产化认证判定对象是发行版用户态而非内核；本系统的业务运行环境（openEuler
   用户态）与信创判定对象完全一致，内核承载方式不构成判定差异；
3. **迁移路径明确**：由于业务与宿主解耦，宿主替换为任意兼容 Linux 内核的国产
   发行版（麒麟、统信、openEuler 桌面版等）仅涉及系统引导与容器运行时的重装，
   业务层零修改。这是容器化架构对国产化长期演进的结构性保障。

## 5. 生态与工程验证

### 5.1 生态事实（官方出处）

| 事实 | 来源 |
|---|---|
| openEuler 源自华为 EulerOS，2021-11 捐赠开放原子开源基金会 | 华为官方新闻 [1] |
| 开源免费 Linux 发行版，多架构支持（x86/AArch64/ARM/RISC-V） | openEuler 官网 [2][4] |
| 统信等信创厂商共建 openEuler 24.03 LTS 生态 | openEuler 官网新闻 [3] |
| openEuler ROS SIG 官方推进 ros1-noetic 软件包适配 | openEuler ROS SIG 门户仓 [5] |

### 5.2 本项目工程验证

- **构建**：基于 `openeuler/openeuler:24.03-lts-sp4` 官方基础镜像构建算法镜像与
  驱动镜像（ROS Noetic、FAST-LIVO2、DAIB-Explorer、EGO-Planner、传感器驱动），
  原生 aarch64 架构；
- **ROS 生态适配**：openEuler ROS SIG 当前提供 ROS Noetic（aarch64）软件源，其中
  部分软件包仍处测试（TEST）阶段——本项目不依赖整仓安装，而是依据算法与驱动
  依赖清单以**显式依赖集**完成构建，保证镜像内容确定、可复现；
- **实机验证**：自 2026 年 8 月起，系统在 Orange Pi 5 Max（RK3588）上完成部署与
  运行验证，传感器时序、SLAM 实时性、分层验收全部通过（记录见本项目部署与验证
  文档 [6]）。

## 6. 结论

- 操作系统层采用国产开源 OS **openEuler 24.03 LTS SP4（aarch64）**，业务全链路
  运行于其容器用户态；
- openEuler 归属开放原子开源基金会治理，源码开放、可获取、可修改，满足自主
  可控判定；信创生态伙伴（统信、麒麟等）共建；
- 宿主 Ubuntu 的角色如实披露为"内核 + 容器运行时"，业务与其零耦合，判定口径与
  信创 OS 一致，且容器化架构为宿主替换国产发行版预留了零修改迁移路径；
- 工程验证完整：官方基础镜像构建、显式依赖集适配测试阶段 ROS 软件源、实机部署
  与分层验收通过。

**判定：操作系统层为国产化技术且自主可控（✅）。**
